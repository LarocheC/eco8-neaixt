# NXP i.MX RT595 — deploy target

Sources live in `deploy/rt595/`. **`deploy/rt595/results/PROVENANCE.md` is authoritative**
and supersedes older prose in `BENCHMARKS.md`, `POWER.md` and `ONBOARD_MEASUREMENT.md`.

## 1. What this target is

EVK-MIMXRT595 (`MIMXRT595SFFOC`), flashed over the on-board LPC-Link2 (CMSIS-DAP/SWD), CDC
console for telemetry. Two compute engines, both at 198 MHz: the **Cortex-M33** and the
**Cadence HiFi4 (Fusion-F1) DSP**. Runtime is TFLite-Micro on both — CMSIS-NN on the M33,
`xa_nnlib` on the HiFi4. The M33 firmware links the SDK's prebuilt cm33 `libtflm.a`; the DSP
build cannot, because the SDK's HiFi4 `libtflm.a` targets the *rt685s* core and fails to link
for `nxp_rt500_RI23_11_newlib` — the RT500 Fusion-F1 is a narrower HiFi4 and lacks several
intrinsics. `tflm/build_rt500.sh` rebuilds `libtflm_rt500.a` from source.

STFT/iSTFT stay on the M33; the model predicts a magnitude mask. `n_fft` 512 / hop 256 =
16 ms at 16 kHz → **3,168,000 cycles per frame**, and 198 MHz was confirmed on silicon on
both cores. The other hard limit is DSP local SRAM: data ≤ 1.24 MB at `0x840000`, text
≤ 1 MB at `0x180400`.

## 2. Results

**One configuration has been measured meeting real time on silicon — NSNet2
`blockdiag_full`, and it does so on the HiFi4, not on the M33.** The M33 runs the same graph
correctly but 1.68× over budget. `blockdiag_8` is also under budget and also fits, but only
in the ISS — no silicon run exists for it.

Dense NSNet2 is fast enough but does not fit: 2.89 MB of int8 weights against a 1.30 MB
`dram0_0_seg`. Monarch fails everywhere tested — its 2-factor permute emits 24 `TRANSPOSE`s
and materialises intermediates that push the arena to 593 K–1,169 K, against 17 K for
block-diagonal.

A flat ISS number is only bindable for an image that fits DSP local SRAM. Dense NSNet2 and
ConvFSENet do not fit, so their cycle figures describe a link that cannot be realised — no
simulation here bounds the PSRAM cost.

All 16 per-frame `mask_checksum` values agree bit-for-bit across CMSIS-NN on the M33 and
`xa_nnlib` on both silicon and the ISS — the load-bearing correctness result, though the
checksum runs on a synthetic pattern and is **not an audio-quality measurement**. On quality,
`blockdiag_full` **matches dense within metric noise at 4× fewer parameters** (701,657 vs
2,783,657): +0.010 PESQ int8, −0.018 FP32.

## 3. Power — MODELLED, not measured

**No ammeter has ever been attached to this board.** The **19–23 mW** inference figure and
**0.14–0.17 mJ per 16 ms frame** are computed from NXP AN13657 and the IMXRT500EC datasheet.
Only two inputs were measured: **VDDCORE = 1.00 V** on-die (`scripts/vddcore_probe.py`, a PMC
low-voltage-detector sweep) and a **46.3 % duty cycle** (7.41 ms per 16 ms frame).
`POWER.md` stages four SWD load states, so metering is a ~15-minute job with hands on the
board.

## 4. Running your own model on it

Paths relative to `deploy/rt595/`. Steps 1–6 need **no board**; 7–8 do.

1. **Checkpoint** — `scripts/fetch_checkpoint.sh <gru|conv|conv-hardened|conv-hardened-deep>`
   fetches **LiSenNet** checkpoints only, from the `claroche1/LiSenNet` HF repo. There is no
   equivalent fetcher for the NSNet2 or ConvFSENet checkpoints in this tree.
2. **Export** — `host/export_tflite_multi.py --model <nsnet2|convfsenet|convfsenet_sliced>
   --checkpoint_file cp_x/g_best --output host_out/<stem> --int8 --calib vbd`. Direct
   PyTorch→TFLite via `litert_torch` + `ai-edge-quantizer`; no ONNX round-trip here (the
   repo README still names the older `ai-edge-torch`). `torch_structured` models also need
   `TORCH_STRUCTURED_BACKEND=torch` and `--repo`.
3. **Int8 calibration** — `--calib vbd` uses `host/streaming_calib.py`, propagating real
   recurrent state over VoiceBank-DEMAND. `--calib flowtest` still propagates state, but
   drives the model with synthetic noise, so its activation ranges do not reflect speech —
   it is an explicit opt-in to a **non-quality-valid** artifact. The failure that
   `streaming_calib.py` exists to prevent is the older *zero-state* calibration, which
   collapsed every state range onto the `3.9215683651783184e-12` calibrator floor and made
   the model run as if stateless (ConvFSENet 9/9 states floored, NSNet2 1/1).
4. **Audit** — `python -m lane audit host_out/<stem>_int8.tflite --resolver
   iss/resolvers/<family>_ops.cpp --tflm-tree $S/tflite-micro --lib $S/libtflm_rt500.a`.
   Exit 0 clear · 1 hard-fail · 2 usage · **3 a deploy-blocking gate could not run**.
5. **C headers** — `host/gen_model_data.py`, `host/gen_io_layout_multi.py` (maps outputs to
   roles by value-matching against torch; emits `MODEL_STATE_MAP`),
   `host/gen_test_feats_multi.py --channels 1`.
6. **Build** — M33: `make -C deploy/rt595 build` (west, `-Dcore_id=cm33` →
   `build/lisennet_se_cm33.{elf,bin}`). HiFi4: `iss/build_dsp_hw.sh` → the three
   `dsp_{reset,text,data}.bin` blobs.
7. **Flash / run** — M33: `scripts/flash_linux.sh` (pyocd over SWD; `scripts/enter_isp.py` +
   `blhost` or LinkServer as alternatives). HiFi4: `scripts/dsp_hw_run.py` boots the DSP
   entirely over SWD in ~40 s — no firmware change, no reflash.
8. **Collect cycles** — the M33 prints `frame, cycles, us, mask_checksum` on
   `/dev/ttyACM0 115200`; `dsp_hw_run.py` reads `g_bench_result` from DSP DRAM. Check the
   checksums against `ONBOARD_MEASUREMENT.md`'s 16 reference values first.

## 5. Without hardware

**`python -m lane audit`** is flatbuffer-only — ~1 s per model, no torch, dataset, board or
simulator. It catches NaN/zero quant scales, ops with no TFLM kernel, resolver mismatches
(including against `app/model_ops_micro.cpp`, the resolver that ships), lost state outputs,
and models that kill the interpreter — but says nothing about cycles, PESQ, or parity with
torch. Without the TFLM tree and library the affected gates **SKIP visibly**, verdict
`INCOMPLETE`, exit 3 — a skipped gate never reads as a passed one.

**The Xtensa ISS** (`iss/build_iss.sh`, then `xt-run
--xtensa-core=nxp_rt500_RI23_11_newlib`) needs the toolchain and licence but no board. For an
image that fits DSP local SRAM, the flat ISS number *is* the silicon number (silicon/ISS =
1.001×). It cannot bound images that spill to PSRAM, and the old `--mem_model` penalty column
should be ignored — a generic-sim-LSP artifact, not a property of this chip.

## 6. Prerequisites

- **NXP MCUXpresso SDK** for EVK-MIMXRT595, `mcuxsdk` flavour (v26.06 here, ~2.4 GB, not in
  the repo) with the eIQ/TFLite-Micro and DSP/Cadence components; symlink to
  `deploy/rt595/sdk`. Plus **Arm GNU toolchain 13.3.Rel1**, CMake ≥ 3.22, Ninja, Python 3.10.
- **Cadence Xtensa toolchain** RI-2023.11 with the RT500 HiFi4 core
  `nxp_rt500_RI23_11_newlib` registered.
- **The Xtensa licence is required via `XTENSA_LICENSE_FILE`, has no default, and is not
  redistributable.** `RT500SDK.lic` is deliberately uncommitted: node-locked to one MAC
  address, expiring 2027-07-28, from the Cadence/NXP account. Scripts fail loudly rather
  than guess a path.
- **LinkServer**, or pyocd with `pyocd pack install mimxrt595sffoc` and
  `scripts/50-cmsis-dap.rules`. Flash from native Linux or Windows — every USB path to this
  board fails under WSL2 usbip.

## 7. Known gaps

- **The HiFi4 silicon run has no committed raw capture.** 1,466,196 cyc/frame was read off
  the board over SWD but survives only as prose; recapturing it takes ~40 s and is the
  largest evidence gap in this target.
- **No power measurement exists** — §3 is entirely modelled.
- **Dense NSNet2 was timed on synthetic weights** (`cp_nsnet2_plain_synth`), its PESQ taken
  from a different checkpoint — valid for shape, never for quality. **The ConvFSENet ISS row
  was measured with a dead recurrent state**, corrected to 2,812,605 cyc/frame.
- **The committed M33 capture is mislabelled** — banner `LiSenNet`, payload
  `nsnet2_blockdiagfull_streaming.tflite`. The firmware now prints `MODEL_NAME` from the
  generated header, so the banner can no longer drift; the capture is kept verbatim.
- **`BENCHMARKS.md` prints two different ISS figures for `blockdiag_full`** — 1,464,615 in
  the silicon-comparison table, 1,464,617 in the sparse-variant table. A 2-cycle
  bookkeeping discrepancy, unresolved; the silicon-comparison value is used above.
- **Resolvers are hand-written** — the committed `app/model_ops_micro.cpp` registers 11 ops
  and no `AddFullyConnected`. An older note concluded NSNet2 therefore "cannot boot on the
  board"; the silicon capture refutes that, because the structured layers lower to
  `BATCH_MATMUL`, which *is* registered, and no `FULLY_CONNECTED` appears in that graph. A
  *dense* NSNet2 graph would need it. Run `lane audit`'s `G-RESOLVER-FIRMWARE` gate against
  the op histogram before trusting a build with a new model.
- **Withdrawn, do not resurrect:** a `dsp_offload` "13.12× speedup / 8080 µs" block
  (illustrative placeholders for a bench that has never run) and a 9.8 KB dense arena figure,
  contradicted by the 17,096 B in the silicon capture. No artifact supports either.
- **Measured but unretained** — distinct from withdrawn. The LiSenNet nc24 M33 figure
  (~21.2 M cyc/frame, ~107 ms, 6.7× over budget) was observed live on the board over VCOM on
  2026-07-23; the console output was watched, not saved. It is a real measurement missing its
  evidence, and it is reproducible — see `deploy/rt595/results/PROVENANCE.md`.
